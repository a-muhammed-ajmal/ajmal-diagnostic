# design-sync notes

Repo-specific gotchas for syncing this design system to claude.ai/design.
Read this before re-running the sync.

## The big one: this repo is an app, not a component library

There is no `dist/`, no Storybook, and no published package entry, so the
converter's normal discovery finds nothing. Two pieces of config carry it:

- **`.design-sync/ds-entry.ts`** — an explicit barrel of the 22 components that
  make up the design system surface. Passed as `--entry`. Deliberately excludes
  `FdiTestStatusForm` (admin-only), `CalendlyWidget` (third-party script wrapper,
  renders nothing offline) and `FdiDiagnosticFlow` (stateful orchestrator).
- **`cfg.componentSrcMap`** — pins all 22 name→source paths. Without it the
  component list is empty, because there is no `.d.ts` tree to scan.

**`--entry` is also what anchors the package root.** Without it the converter
looks for `node_modules/ajmal-diagnostic/package.json`, which npm never creates
for a repo's own package, and dies with ENOENT before doing anything.

Keep `ds-entry.ts` and `componentSrcMap` in agreement when adding a component.

## Never put a `"//"` key in tsconfig.sync.json

This cost a full debugging cycle. `tsconfigPathsPlugin` strips `//` line comments
before `JSON.parse`, so a key literally named `"//"` truncates the file, the parse
throws, and the plugin returns `null` — **silently disabling every path alias**.
Use `"_comment"` instead.

Symptoms when it happens: `next/link` gets bundled for real, the bundle throws
`ReferenceError: process is not defined` at eval time, `window.ConsultingDS` is
never assigned, and validate reports `[BUNDLE_EXPORT] 22/22 not a component`.

## Next.js imports are shimmed, not bundled

`.design-sync/shims/next-link.tsx` and `next-navigation.ts` are aliased in
`tsconfig.sync.json`. Without them the DS bundle pulls Next's router internals
(+350KB) and every preview needs a router context it cannot have. `usePathname()`
returns `"/"`, so `Navigation` and `Footer` preview in their home-active state.

## CSS must be compiled by us

Tailwind v4 has no config file — the theme is the `@theme` block in
`src/app/globals.css`, and utilities are generated by scanning source. The app
gets that from Next's PostCSS pipeline, which the bundle has no access to.
`.design-sync/build-css.mjs` (wired as `cfg.buildCmd`) runs the same Tailwind
version over the same input and **binds `--font-figtree` / `--font-roboto-slab`**,
which `next/font` supplies at runtime in the app. Those bindings are not optional:
an undefined custom property invalidates the entire `font-family` declaration, so
without them every component falls back to a system font.

Consequence worth knowing: the shipped stylesheet contains only the ~640
utilities the site actually uses. See `conventions.md` — the design agent is told
about this explicitly.

## Fonts are self-hosted

`.design-sync/fetch-fonts.mjs` downloads the exact faces `layout.tsx` requests
(Figtree 300–700, Roboto Slab 500–800, latin) into `.design-sync/fonts/`, wired
via `cfg.extraFonts`. A remote Google Fonts `@import` would have satisfied
validate as `[FONT_REMOTE]`, but self-hosting matches what the site does and
removes a render-time network dependency. **Re-run `fetch-fonts.mjs` if
`layout.tsx` changes its weights or subsets.**

## Smaller traps

- The tsconfig paths plugin resolves a **bare directory** before trying
  `/index.ts`, and esbuild then fails on the directory. Import
  `@/lib/fdi/config/index`, not `@/lib/fdi/config`.
- Changing `cfg.overrides` fails `preview-rebuild.mjs` with `[CONFIG_STALE]` —
  a full `package-build.mjs` is required to re-stamp grade keys.
- A full `package-build.mjs` clears `ds-bundle/_screenshots/review/`. Grades
  survive (they follow sources), but sheets must be re-captured before grading.
- `playwright@1.62.1` matches the already-cached `chromium-1234`, so no browser
  download is needed. Check `playwright-core/browsers.json` if that cache moves.
- Shell heredocs here mangle backslashes in regexes — write analysis scripts to a
  file rather than using `node -e`.

## Design-system findings (about the repo, not the sync)

- **`SectionHeader` is light-ground only.** It hardcodes `text-ink` for the title
  and `text-brand-ink`/`text-accent-ink`/`text-danger` for the eyebrow. On a
  `tone="dark"` Section the title is invisible and the eyebrow lands near 1.5:1.
  The site works around this by writing inverted markup directly
  (`src/app/page.tsx`). A `SectionHeader` dark variant would remove the trap.
  The `Section` preview's `DarkBand` cell documents the workaround.
- `Footer` renders a hardcoded `© 2024` line while the repo's current year is
  2026 — worth a look, independent of this sync.

## Known render warns

None. `package-validate.mjs` exits 0 with no warnings — 22/22 previews render
cleanly. **Any warn on a future run is new**: investigate it rather than
assuming it was always there.

## Preview conventions used here

- Layout glue inside previews is **inline-styled**, not Tailwind, because a
  utility used only in a preview may not exist in the compiled stylesheet.
  Anything that should carry brand styling is a real DS component.
- Wide/desktop-only compositions declare a viewport in `cfg.overrides`
  (`cardMode: "column"`). `ArticleToc` and the `PageHero` 7/5 split literally do
  not render their real layout below `lg`.
- `FdiResults` seeds `sessionStorage` by running the product's **own** scoring
  pipeline (`scoreFdi` → `buildReport` → `toFounderFdiReport`) over the raw
  target `{DS:6, EC:6, OV:6}` — the one `public-report.test.ts` uses. Every figure
  on that card is genuine engine output, not an invented metric.

## Re-sync risks

- **`ds-entry.ts` and `componentSrcMap` are hand-maintained.** A component added
  to `src/components/` will NOT appear until it is added to both. Nothing warns.
- **`build-css.mjs` hardcodes the path to the staged Tailwind CLI**
  (`.ds-sync/node_modules/@tailwindcss/cli`). On a fresh clone, re-run the
  staging `cp -r` and `npm i` in `.ds-sync/` first, and keep the CLI version
  matching the repo's `tailwindcss` (4.3.0 at time of writing).
- **The font weights in `fetch-fonts.mjs` mirror `layout.tsx` by hand.** If
  `layout.tsx` adds a weight, the bundle will silently synthesise it.
- **Previews import repo internals** (`@/lib/questions`, `@/lib/fdi/*`). A
  refactor of those paths breaks preview compilation — the component still ships,
  but drops to a floor card. Watch for `! preview build failed:` in the build log.
- The FDI preview depends on `src/lib/fdi/test-support.ts` remaining exported.
- Grades live in the gitignored `.design-sync/.cache/`; cross-machine carry-forward
  comes from the uploaded `_ds_sync.json`, not from git.
